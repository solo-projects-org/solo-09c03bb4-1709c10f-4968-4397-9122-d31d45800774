# 病区 × 周次 阳性检验安全汇总发布

医院感染控制数据员使用的内部小工具：上传检验 CSV，生成带行列合计的
“病区 × 周次”阳性检验交叉表，按保密规则隐藏小计数值，网页预览确认后发布，
供研究组查看比较；发布后可用递增修订号上传完整修订 CSV 核查，判断已发布
汇总能否继续供研究组使用。FastAPI + SQLite，Docker Compose 一键启动。

## 快速启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库保存在命名卷 `app_data`（容器内 `/data/app.db`），
容器重启/重建后已发布表仍可查看。

本地开发（不用 Docker）：

```bash
pip install -r requirements-dev.txt
pytest                      # 运行自测（58 个用例）
uvicorn app.main:app --reload --port 8000
```

## 使用流程

1. **上传**：在“上传”页选择检验 CSV。
2. **预览**：校验通过后生成安全表预览（隐藏格显示为“—”）；
   确认前可重新上传替换预览，或放弃。
3. **确认发布**：点击“确认发布”，原子写入 SQLite。
   **确认后不再接受替换文件**（上传接口返回 409）。
4. **查看**：已发布页 `/published` 随时可查，重启后仍在。
5. **修订核查**：同一批检验修订后，由数据员在已发布页输入递增修订号、
   上传该修订的**完整 CSV**，系统对照已发布汇总判断能否继续供数（见下节）。

任何失败（CSV 校验失败、同号冲突、无法安全发布）都不会产生
部分公开结果：不展示表格、不改变已有状态。

## 修订核查

已发布页底部有“修订核查”表单：**修订号 + 该修订的完整检验 CSV**。

- **解析**：按检验号去重；同一检验号内容冲突则整份拒绝（400），
  与上传流程一致。修订后病区/周次集合**允许变化**，因此不再要求
  2～3 个病区、2～3 个周次。
- **对照**：与已发布表比较病区集合、周次集合、公开格数值、
  行合计、列合计、总计。隐藏格数值不属于公开信息，不参与比较。
- **结论**：
  - 范围或任何公开值变化 → **撤下**旧表：已发布页只显示撤下状态、
    撤下原因与修订号，**不再展示表格**，不泄露任何隐藏格计数；
  - 未变化 → 已发布表**继续供研究组使用**。
- **持久化**：核查结论与最高修订号写入 SQLite，重启后保持。
  - 同一修订号必须是同一份文件（内容指纹按去重后的记录计算，
    行序/重复行不影响）；同号不同文件 → 409，状态不变。
  - 修订号须递增；较旧修订即使**晚完成**也不能覆盖较新结论（409）。
  - 撤下是**单向**的：一旦撤下，后续核查（包括公开信息与旧表一致的
    更新修订）都不会自动重新公开，页面保留首次撤下的修订号与原因。
- **无效上传**（修订号非法、编码/格式错误、同号冲突、文件过大）
  只提示错误，现行核查状态与表格保持原样。

示例：先发布 `samples/ok_3x3.csv`，再依次用
`samples/revision_unchanged.csv`（修订 1，继续供数）与
`samples/revision_changed.csv`（修订 2，撤下）核查。

限制说明：发布后已发布表本身仍不可修改；撤下后如需新的汇总，
需由运维按新数据重新初始化发布流程（本工具不提供“重新发布”接口，
以避免误将撤下状态覆盖成公开）。

## CSV 格式

首行为表头，须包含四列（UTF-8，可带 BOM）：

```csv
检验号,病区,周次,是否阳性
A001,内科,2026-W44,是
A002,内科,2026-W44,否
A003,外科,2026-W45,阳性
```

- `是否阳性` 可填：是/否、阳性/阴性、1/0、true/false、y/n。
- 文件须覆盖 **2～3 个病区、2～3 个周次**（按全部记录计，含阴性）。
- **同一检验号**内容完全相同的记录只计一次；内容冲突（病区/周次/
  阴阳性任一不同）则**整份拒绝**。
- 交叉表统计各“病区 × 周次”的**阳性**检验数（按检验号去重）。

示例文件见 `samples/`：`ok_3x3.csv`（可发布）、`conflict.csv`
（同号冲突，拒绝）、`unpublishable_2x2.csv`（2×2 含小格，无法发布）、
`revision_unchanged.csv` / `revision_changed.csv`（修订核查示例，见下节）。

## 保密规则

- 计数为 **1～2** 的格必须隐藏（一次隐藏）。
- 可**连带隐藏**其他格，但结果必须满足：
  1. 每行、每列至少保留一个公开格；
  2. 在“公开格取值 + 行合计 + 列合计”已知的前提下，每个隐藏格
     **至少有两种非负整数可行取值**（不能被行列合计唯一倒推）。
- 不存在满足条件的隐藏方案时，判定**无法发布**，仅提示原因。

实现要点（`app/suppression.py`）：隐藏格视为 ≥0 整数变量，公开格固定，
行列合计公开；二维列联表给定边际合计的可行性是运输问题，用最大流
（整数容量 ⇒ 整数解）精确判定；每个隐藏格的可行取值区间通过对上/下界
二分求得，区间宽度 ≥1 即满足“至少两种取值”。隐藏方案按连带隐藏格数
最少优先（对子集做 BFS，3×3 至多 2⁹ 个子集）。

注意：不足 3 行或不足 3 列的表，只要存在小格就无法发布——任何隐藏格
都会被其所在行/列的合计与其余公开格唯一确定，而再连带隐藏就会使某
行/列没有公开格。

## 目录结构

```
app/
  main.py          FastAPI 路由与流程（上传/预览/确认/查看/修订核查）
  csv_import.py    CSV 解析、校验、去重、冲突检测、交叉表
  suppression.py   保密隐藏规则与最大流可行性判定
  revision.py      修订核查：内容指纹与已发布公开信息的对照
  db.py            SQLite 持久化（pending / publication / revision_check）
  templates/       Jinja2 页面
  static/style.css
tests/             pytest 自测（隐藏规则 / CSV / Web 全流程 / 修订核查 / 状态事务）
samples/           示例 CSV（含修订示例）
Dockerfile, docker-compose.yml
```
